# Data-protection statement

The statement of SPEC §20.2, published after each sentence was checked against the implementation (PLAN C1.04, docs/DECISIONS.md D-046). Sentence 3 was reworded in the spec to match the code: it used to say every agent action passes the policy engine, which is true only of messages to customers. `tests/test_data_protection.py` keeps this page true: the statement below must equal the spec's, and every file and test named as evidence must exist.

## Statement

<!-- STATEMENT:START -->
The competition prototype uses a fictional, seeded receivables dataset. It does not require or contain real company ledgers or customer correspondence. Financial calculations are deterministic; LLM output cannot change ledger amounts. Agent actions are limited to a fixed tool registry, an autonomy level and a kill switch; every message to a customer also passes a deterministic policy engine. Outbound messages are written to a local sandbox outbox only. Inbound message content is treated as untrusted input and tested against instruction-injection attempts. Logs and demo artefacts are designed to exclude secrets and personal data. Simulator outcomes are illustrative and are not presented as evidence of real-world collections improvement.
<!-- STATEMENT:END -->

Redaction alone does not make real customer data safe for an external model: it removes emails, phones, TRNs, IBANs and customer names in the usual formats only (SPEC §7.5, D-030). If the product later handles real data, this statement must be updated after a security, privacy, contractual and legal review.
